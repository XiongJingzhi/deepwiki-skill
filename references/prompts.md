## 代码深度分析

分析代码文件，提取完整的语义信息：

```
深度分析以下代码文件：

文件: {{ FILE_PATH }}
语言: {{ LANGUAGE }}
完整代码内容:
{{ CODE_CONTENT }}

### 语言术语规范

根据文件扩展名检测源语言，使用对应的术语：

| 语言 | 扩展名 | 函数/方法术语 | 文档注释风格 |
|------|--------|---------------|-------------|
| JavaScript/TypeScript | `.js` `.ts` `.tsx` | function | JSDoc (`/** */`) |
| Python | `.py` | function | docstring (`"""`) |
| Java | `.java` | method | Javadoc (`/** */`) |
| C# | `.cs` | method | XML doc (`///`) |
| Go | `.go` | function / method | `//` comments |
| Rust | `.rs` | fn | `///` / `//!` doc comments |

### 文档注释提取

- **JS/TS/Python/Java/C#**：从文档注释（`/** ... */`、`"""..."""`、`/// ...`）中提取文档。保留 `@param`、`@returns`、`@throws`、`@deprecated` 标签。
- **Go**：从导出标识符前的 `//` 注释中提取文档。注意 `// Deprecated:` 注解。示例：`// NewClient creates a new client...` 文档化 `NewClient`。按导出标识符分组；将 `// Deprecated:` 映射为已弃用状态。
- **Rust**：从 `///`（条目文档）和 `//!`（模块文档）注释中提取文档。保留 `# Examples` 代码块、`# Panics`、`# Errors`、`# Safety` 章节。将 `#[deprecated]` 属性映射为已弃用状态。

请进行 **全面深度分析**，输出以下信息：

## 1. 模块概述
- **核心职责**：详细描述模块解决什么问题，为什么需要这个模块（3-5 句）
- **设计理念**：采用了什么设计模式/架构思想，为什么这样设计
- **在系统中的位置**：与其他模块的关系，在整体架构中扮演什么角色

## 2. 公开接口（每个接口详细说明）
对于每个导出的函数/类/类型：
- 名称、签名、行号
- **详细描述**：做什么、怎么做、什么场景使用（不少于 2 句）
- **参数说明**：每个参数的含义、约束、默认值
- **返回值说明**：返回什么、可能的值、错误情况
- **使用示例**：实际代码示例
- **注意事项**：边界情况、性能考量、常见错误

## 3. 内部实现（帮助理解代码逻辑）
- **核心算法/逻辑流程**：用 Mermaid flowchart 展示
- **关键数据结构**：内部使用的重要数据结构
- **状态管理**：如果有状态，说明状态变化

## 4. 依赖关系
- **内部依赖**：依赖哪些项目内模块，为什么依赖
- **外部依赖**：使用哪些第三方库，用来做什么
- **被依赖**：哪些模块依赖本模块

## 5. 扩展性与维护
- **如何扩展**：添加新功能的推荐方式
- **潜在改进点**：可以优化的地方
- **测试建议**：关键测试场景

输出格式：结构化 YAML，包含上述所有字段
```

## 生成要求

### 1. 概述（模块概览）
- 用 2-3 段文字描述模块的目的、解决的问题、核心价值
- 说明模块在整体系统架构中的角色
- 包含架构位置图（Mermaid flowchart，高亮当前模块）

### 2. 核心类与函数
- 核心特性表格：| 特性 | 说明 | 相关接口 |
- **classDiagram**：展示核心类/接口的属性、方法、关系
  ```mermaid
  classDiagram
  class ClassName {
    +property1 : Type
    +method1(param : Type) : ReturnType
  }
  ClassName --> RelatedClass : 依赖
  ```
- 图表来源引用

### 3. 文件结构
- 列出每个文件及其职责（不只是文件名）
- 说明文件之间的关系
- 用表格呈现：| 文件 | 职责 | 导出内容 |

### 4. 公开接口
- 接口总览表：| 接口 | 类型 | 描述 | 源码 |
- 对每个公开接口详细说明：
  - 签名 + 源码链接
  - 参数表格（含约束和默认值）
  - 返回值说明
  - 完整使用示例（可运行的代码）
- 类型定义及字段表格（如适用）

### 5. 代码示例
提供 2-3 个示例，使用项目的主要语言：
- **示例 1：基础用法** — 最简上手示例，含预期输出
- **示例 2：进阶用法** — 完整配置/高级选项
- **示例 3（可选）：错误处理** — 展示异常捕获和恢复

### 6. 依赖关系
- 依赖关系图（Mermaid flowchart LR）
  - 本模块依赖的模块（内部 + 外部）
  - 依赖本模块的模块
- 依赖说明表：| 依赖模块 | 用途 | 耦合程度 |

### 7. 错误处理与边界情况
- 可能的错误类型及触发条件
- 错误处理建议
- 调试技巧
- 边界情况和常见陷阱

### 8. 相关文档
- 架构文档中的相关章节链接
- API 参考链接
- 相关模块文档链接
- 外部资源

## 依赖关系分析

> 对应 SKILL.md 第 3.5 步：在深度阅读源码后执行，将孤立的文件分析转化为连贯的架构依赖图。

```
根据以下代码洞察生成 **项目依赖关系图**：

高优先级文件洞察（importance_score >= 0.6）:
{{ HIGH_PRIORITY_INSIGHTS }}

每条洞察格式：
[组件名] | [角色标签] | [文件路径] | [重要性评分] | [复杂度] | [依赖项列表]

---

## 分析要求

请生成一份结构化的依赖关系分析，包含以下三个部分：

### 1. 核心依赖关系（core_dependencies）

列出项目中最重要的模块间依赖边，每条依赖包含：
- **from**：来源模块/文件名（不含路径前缀）
- **to**：目标模块/文件名
- **type**：依赖类型，必须为以下之一：
  - `Import` — 文件级导入（use/import/require 语句）
  - `FunctionCall` — 运行时调用依赖
  - `Inheritance` — 类继承/接口实现（extends/implements）
  - `Composition` — Has-a 结构（字段持有、组合关系）
  - `DataFlow` — 数据流动（API 载荷、共享状态、消息传递）
  - `Module` — 模糊依赖（当上述类型均不确定时使用）
- **importance**：重要性 1-5（5 最重要，基于被依赖频率和模块重要性评分）
- **description**：一句话描述依赖原因（可选）

### 2. 架构分层（architecture_layers）

将所有组件按架构层次归组，每层包含：
- **name**：层名称（如"展示层"、"业务逻辑层"、"数据访问层"、"基础设施层"）
- **level**：层级数字，数字越小越接近基础设施（1 = 最底层）
- **components**：属于该层的组件名列表

### 3. 关键洞察（key_insights）

3-5 条自由文本的架构观察，重点关注：
- 核心枢纽模块（被多个模块依赖的组件）
- 潜在的循环依赖（A 依赖 B，B 又依赖 A）
- 架构边界违规（跨层调用）
- 高耦合模块（依赖数量 > 10）

## 输出格式

严格按以下 JSON 结构输出，不要包含任何 JSON 以外的内容：

\`\`\`json
{
  "core_dependencies": [
    {
      "from": "模块A",
      "to": "模块B",
      "type": "Import",
      "importance": 4,
      "description": "模块A 通过 import 依赖模块B 的工具函数"
    }
  ],
  "architecture_layers": [
    {
      "name": "业务逻辑层",
      "level": 3,
      "components": ["service_a", "service_b"]
    }
  ],
  "key_insights": [
    "utils 模块是核心枢纽，被 12 个模块依赖，建议拆分",
    "发现潜在循环依赖：auth_service → user_service → auth_service"
  ]
}
\`\`\`

**注意事项**：
- 依赖类型必须严格使用上述 6 种之一，不要创造新类型
- importance 必须是 1-5 的整数
- level 必须是正整数
- 如果 description 内容不确定，可省略该字段
- 最多输出 50 条 core_dependencies，按 importance 降序排列
```
